## Alignment and ownership

- Folder sections have a 28px compact chevron button in the heading's former icon slot (#425),
  with a 16px icon and the existing 8px name gap. The target is centered on the first text line;
  it moves with the first word on wrapping names, keeps clear of the top-right actions and uses
  existing tokens. It rotates like subfolder chevrons. The name/title and wrapping rules below
  are retained. Collapsing hides only the tree/empty help; heading controls remain reachable at
  desktop, 200px narrow-sidebar and phone full-screen widths. See the
  [section contract](editor-ux-shell-v1.md#collapsible-folder-sections-425).

- The expanded Sidebar header places a single Open folder… icon button before Collapse sidebar, grouped by `--space-1` (4px), with the existing `--size-control-compact` (28px) target and `--size-icon-slot` (16px) icon. The header keeps its 48px height. The entry stays in place with zero/one/several folders; no duplicate empty-panel or per-folder Open entry. It fits the 200px narrow sidebar and the phone full-screen sidebar. The collapsed rail contains only the 28px Expand sidebar entry. See [#385 evidence](editor-ux-shell-v1.md#sidebar-open-folder-entry-385).

- Sidebar icons use a 16px slot and 8px label gap. A tree row is a 16px chevron slot (empty for documents), 4px, the icon and the name; top-level rows share one icon start and one text start within 1px. Each level indents 12px, at most five levels; deeper names keep that indent and ellipsize, with the full path in `title`.
- Each opened folder is its own section in the order opened (#235), separated by `--space-3`. One opened folder keeps its heading in place while its tree scrolls; with several, the Files panel scrolls them together as one list, so every heading and item stays reachable without overlapping.
- Each folder heading shows its whole name without hover (#218). Its 28px New file / New folder / More actions stay at the top right as one group without gaps between the ghost buttons (their 16px icons stay 12px apart) and 4px before the name; text wraps around them, then uses the full remaining text width below, keeping the existing horizontal icon and text starts. Korean words stay together (`word-break: keep-all`). The icon and first word move together below the actions when the word cannot fit beside them; a word wider than the full text column still wraps with `overflow-wrap: anywhere`. Names that fit beside the actions keep the same single-line appearance. The first line matches the compact control height; later lines use the 20px UI rhythm. No horizontal overflow, ellipsis or line limit is applied. The full path remains in `title`. Tree entry truncation is unchanged.
- Sidebar and docked Document panel headers stay 48px. TopBar stays 48px when its actual available width is at least 56rem; below that container width, the centered command trigger gets its own row above status and actions. Below 35rem the sidebar entry and Document settings share a row above the view/file controls; status has a separate row when nonempty. Groups and controls wrap in order at phone widths so every action stays inside the viewport.
- The document tab row sits below TopBar inside the sticky header, sharing its inline inset. Its compact 32px height and maximum tab width use `--layout-document-tab-height` and `--layout-document-tab-max-width` (Adjustable values). The activation area fills the token-defined height with only inline padding; the 28px close target and independent inset focus rings fit inside it. The row alone scrolls horizontally; each tab fits within the available row width, its label ellipsizes and its 28px close target remains visible. The header measurement includes this row; heading scroll margins and overlay height limits deduct the whole measured header. Save stays in TopBar above it at 375px.
- TopBar and MessageArea share a 20px inline inset. The command-center trigger is centered in the TopBar and capped at 28rem, using a 32px control and 16px search icon. It leads with the search icon and Find documents and commands / 문서·명령 찾기; location/name is muted secondary information. Equal side tracks reserve 21rem each for document/view actions; the centered button takes the remaining space, from a 10rem (160px) minimum to the existing 28rem cap. The secondary location/name yields first, then the shortcut; the action label ellipsizes last (#556). The full shortcut remains in the tooltip and keyboard contract. Status has a separate left cell (or its own phone row), so a status change moves no control horizontally (0px, measured).
- TopBar places Document settings in its document area. View controls (Visual/Source, Wide document, Outline) and file action groups keep their order, separated by 12px between groups and 4px within groups. Visual/Source is one segmented control: a 28px track with 2px padding holding two 24px segments. Visual/Source raised faces and their painted control-color edges do not affect layout; document tabs instead use a flat surface with a bottom accent marker (#581). Both retain independent inset focus rings; tab text stays at 0px movement. Current Files/Outline/+·slash rows intentionally use 600 semibold as a non-color cue, so glyph widths may change. Files retains ellipsis; Outline reserves its semibold text extent with a hidden copy and keeps the two-line clamp to avoid row-height jumps. Hover/focus preserve the current weight and existing insets.
- The document column centers in the area remaining between the sidebar and the Document panel. Its maximum width is `--layout-content-width` (928px), or `--layout-content-width-wide` (1280px) with the Wide document preference, with 16px outer insets; it never exceeds the available area. Both values are [adjustable values](editor-visual-language-v1.md#adjustable-values-and-preferences). Wide changes only the column width: the content axis, 80px gutter and block rules stay the same.
- Document owns the 80px starting gutter: 8px edge + 28px control + 4px gap + 28px control + 12px safety. Trailing inset is 80px, becoming 16px at ≤1024px.
- The white document surface fills at least the viewport below the measured sticky header, less two outer insets. The column's 16px canvas gap surrounds it; an inset 1px edge changes no width. Long documents grow naturally and end with the adjustable writing end space (`--layout-document-end-space`) as bottom padding. The blank paper below the actual editor content remains clickable to continue writing.
- All top-level block wrappers share the content axis. Block-internal content may inset or center. Controls overlay the gutter and never shift text. The pointer-hover extent starts from the drag-source rectangle (content axis, block top/height, trailing document inset), expanded by `--space-block-hover-inline` (8px left/right) and `--space-block-hover-block` (4px above/below). This uses 8px of the 12px gutter safety, leaving 4px before the handle, and keeps neighboring extents separate within the existing block gaps. The hover corner radius is `--id-radius-block-hover` (small radius plus the existing 4px selection outline offset and 1px stroke width, currently 9px). Figure/Equation selected/editing elements use that radius minus their unchanged offset and stroke width, matching the painted outer corner radii. The hover stroke is inset, so its outer radius is the overlay radius. No content border/padding is added: text moves 0px. Hover uses the original vertical block range anywhere inside the document host, including its gutter controls; expansion does not activate the gaps. Gutter, hover and drag geometry observe both the paper and editor content, so content resizing inside a minimum-height paper still updates the handles and overlays. The hover extent is recomputed under the pointer on layout/scroll/transactions, independently of selection; geometry updates do not switch its controls to the selection.
- Expanded sidebar width is `--layout-sidebar-width` (240px), or `--layout-sidebar-width-narrow` (200px, so a short folder name fits beside its actions) at ≤1024px; both are [adjustable values](editor-visual-language-v1.md#adjustable-values-and-preferences). It is 48px when explicitly collapsed. Below 640px, at phone widths (`width < 40rem` in `styles.css`, which zeroes the sidebar's grid width before React reacts, and `SIDEBAR_OVERLAY_LAYOUT` in `App.tsx`), the sidebar takes no grid width (#321): closed, it has no rail and the document uses the whole width, with a 28px Expand sidebar control first in the TopBar identity; opened, it covers the whole viewport. It starts closed. Escape inside it, its Collapse control, or opening or creating a document from it closes it again; crossing 640px starts it in that layout's default. The collapsed rail contains only Expand sidebar. Folder-specific New/Close actions appear in expanded file navigation; Open folder stays in the header. Document settings uses 14px choice labels, 12px help and 16px native checkboxes inside at least 28px label targets, within the shared scrolling dialog.
- The Document panel is `--layout-document-panel-width` (256px, an adjustable value) and docks at 1424px and wider; closed, it takes no width. The docking width is separate from the 1024px narrow sidebar so the document keeps a readable width beside both panels: at 1424px, 1424 − 240 − 256 = 928px remains, preserving the Standard column (736px of text after outer and inner insets). At 1280–1423px it stays closed by default, preserving the 928px Standard column and single-row TopBar; the former 1280px docking rule left only 592px of text. Below 1424px the panel never takes grid width: opened, it overlays at its width against the right edge (at most the viewport), from the bottom of the sticky header (TopBar and messages, measured as `--app-header-height`) to the bottom of the viewport, and the document keeps its width. When resizing below the docking width, CSS immediately hides any still-mounted docked panel until the media-query state update closes it, so its header cannot overflow the zero-width column. Explicitly opened overlays remain visible. Returning to the docked layout restores the user's last explicit docked open/closed choice, or opens by default if none exists. Overlay interactions do not replace that docked choice; each transition into overlay starts closed. This choice lives only in page memory and resets on reload. The docking width is a media query (`width < 89rem` in `styles.css` and `PANEL_OVERLAY_LAYOUT` in `App.tsx`), not an adjustable value.

## Controls and spacing

- Dedicated Settings (#594) covers the viewport with a 48px minimum header, the existing
  240px sidebar width and a bounded 680px content column (`--layout-settings-content-width`).
  Label/description and control columns share row axes; selectors use the adjustable
  `--layout-settings-control-width` (240px) and existing 32px control tokens. Content uses
  the 64px inline/32px block spacing scale; below 768px the named category list stacks above
  content with 24px content insets and single-column rows. The body scrolls inside the
  viewport, leaving Back reachable. No document or shell geometry changes underneath it.

- The [folder dialog](folder-picker-v1.md#folder-presentation-522) keeps one column at wide and phone widths. Its folder-only child list has a 16rem maximum (eight standard 32px rows); longer lists scroll and the enclosing dialog remains scrollable for short viewports. The shared image mode retains its 15rem bound. Starting-place names wrap inside the column, retaining the whole name and path description; New folder shares the child-list heading row. Ancestor breadcrumbs retain wrapping and disappear with Up at the Root.

- B1 (#514): standard controls/inputs 32px; compact controls/actions/fields 28px; control radius 6px; UI text 14/20px; line icons 16px. Use Button/Input and existing size/radius/UI tokens; do not derive control metrics from document type. Measure actual rendered height after transitions complete. Role-specific exceptions and reasons are in [Visual Language](editor-visual-language-v1.md#deliberate-control-exceptions): document-sized title/inline/backlinks, metadata, tab/close slots, native checkbox and wrapper-owned path field, 24px inner view segment, multiline fields, wrapping breadcrumbs/list rows and content/surface radii.
- Existing 4/8/12/16/20/24/32/48/64px spacing scale remains. The paper starts 16px below the header; its adjustable top block padding is 32px (16px at ≤1024px), keeping the content start at 48px (32px at ≤1024px), before block margins.
- Body: 17/28.9px; UI/caption/table: 14/20px; metadata/status: 12/16px. Heading values and spacing are in Visual Language (current v4.8).
- Paragraph/block gaps: 16px. Heading before/after: 32/12px. Figure caption gap: 8px.
- Figure, Equation and Table authoring metadata takes no layout space: it is positioned in the block gap above its block, right-aligned and clear of the hover outline. A table's 28px row and column handles keep a 32px handle gutter (`--size-table-handle-gutter`): the column handles above the table and the row handles left of the text axis, so the table itself starts on the text axis. Its Edit (caption and label), Table actions and Delete sit together in the action bar below it, starting at the table's start beside Append row, so a table wider than the column keeps them in view before it is scrolled.
- Table tools use compact shared Buttons with 6px radii; column width follows the column and row targets stay centered at 28px. B2 (#517) uses centered 16px horizontal column / vertical row line icons in those same hit areas, with address names/tooltips; the layout/command target is unchanged. Breadcrumbs use 28px minimum shared Button geometry with 6px radii and wrapping; the code language uses a recognizable 28px Input. Tiny inline reference/citation edit/remove controls retain the explicit line-height/neighbor-hit-area exception described in Visual Language. Expanded Sidebar Collapse has quiet transparent rest with its disclosure semantics preserved.
- Endnote definitions: one trailing region, 16/24px text, 24px number inset and space before/after the region, 8px between definitions. Only the first has a 1px rule, 12px to the 12/16px `미주` label, then 8px to the definition. Original source disclosures keep their existing dimensions; the [Endnotes contract](footnotes-v1.md#endnotes-presentation) defines display order and source conversion.
- `components/ui` and legacy native primitives share product tokens; refs, events and selection are preserved.

## Exceptions and checks

- TopBar prioritizes its search action, with optional muted location/name; the full unchanged address remains in the secondary information title.
- Tables and formulas scroll inside their block, with a thin scrollbar where the platform draws one and a fade (`--size-overflow-fade`) at an edge with more content; the fade follows the scroll position and is absent without overflow. Source soft-wraps Markdown lines, including unbroken text, within the available width without horizontal scrolling (#476). Each source line has one gutter number; continuation rows align with its text, leaving the number gutter clear. Wrapping is display-only and preserves source text/Copy. Overlay contents may scroll if viewport height demands it. Never hide overflow on the whole document or restyle KaTeX internals to make measurements pass.
- Overlay positioning respects the viewport and sticky header. Required controls must exist and stay reachable.

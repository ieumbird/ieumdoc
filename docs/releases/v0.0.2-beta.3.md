## 준비 단계 작업 계획

- 범위: Desktop 후보를 `0.0.2-beta.3`으로 올리고 opt-in 실제 GitHub 업데이트 harness의 향후 대상을 `0.0.2-beta.2 → 0.0.2-beta.3`으로 맞춘다. 공개 버전과 후보를 구분해 문서·색인과 한국어 Release 본문 초안을 준비한다.
- 제외: 기능 코드 변경, tag 생성, release workflow 실행·게시, 병합, 로컬 앱 실행·설치. PATH·레지스트리·IeumDoc 사용자 데이터를 변경하지 않는다.
- 완료: 대상 로컬 검사와 준비 PR의 필수 CI가 통과하고 `Refs #690` PR을 오케스트레이터에 전달한다. 게시와 공개 후 기록 PR은 오케스트레이터가 별도로 진행한다.
- 검증: Desktop 단위 테스트·typecheck, 문서·공백 검사. package·release 자산 검증과 packaged·install/update·uninstall은 로컬에서 실행하지 않고 disposable Windows CI에 맡긴다. 브라우저는 실행하지 않는다.

CI local-feed fixture는 Stable `0.0.1 → 0.0.2`, Beta `0.1.0-beta.1 → 0.1.0-beta.2`를 유지한다. 현재 소스를 테스트 버전으로 각각 빌드하는 경로이며 공개 자산을 쓰는 실제 GitHub `LIVE` 경로와 구별한다.

## 공개 자산

공개 전이므로 크기·해시와 installer SHA-512는 공개 다운로드 대조 후 별도 PR에서 채운다. 로컬 후보나 이전 버전의 해시를 공개 근거로 쓰지 않는다.

| 파일 | 크기 (bytes) | SHA-256 |
| --- | --- | --- |
| `beta.yml` | 게시 후 기록 | 게시 후 기록 |
| `IeumDoc-Setup-0.0.2-beta.3.exe` | 게시 후 기록 | 게시 후 기록 |
| `IeumDoc-Setup-0.0.2-beta.3.exe.blockmap` | 게시 후 기록 | 게시 후 기록 |

Installer SHA-512와 `beta.yml`의 version/path/files/hash/size 대조: 게시 후 기록.

## 알려진 제한과 수동 확인

- unsigned Beta이며 Authenticode 게시자 인증을 제공하지 않는다. 체크섬은 무결성 검증이며 SmartScreen·조직 보안 정책 경고가 나타날 수 있다. Stable은 미공개다.
- 개발 단계이므로 이전 이음독 문서·복구 기록·설정의 하위 호환성과 자동 migration을 보장하지 않는다. 중요한 문서는 별도로 백업한다.
- #528로 기존 샘플 사본 `sample-native-v1`이 교체될 수 있다. 수정한 샘플 내용도 교체 대상이지만 앱이 소유를 확인한 경우에만 교체한다. 확인되지 않은 폴더는 보존하며, 구체적인 소유 확인·안전한 교체 조건은 [샘플 계약](../design/desktop-distribution-v1.md#native-sample)을 따른다.
- 실제 GitHub `0.0.2-beta.2 → 0.0.2-beta.3` 업데이트는 **미실행·미검증**이다. [실제 GitHub 검증 절차](../test/README.md#real-github-beta-update)와 CI local-feed 결과를 구별한다.

다음은 별도 수동 확인 항목이며 이 준비 작업에서는 실행하지 않는다. 자동화·CI 성공으로 실제 사용자 환경 수용성을 판정하지 않는다([수동 확인 경계](../test/README.md#manual-review)).

- 실제 Windows 창 드래그·더블클릭 최대화
- 한글 IME 수식 입력
- Desktop CLI 켜기·끄기
- 탐색기에서 폴더 열기 (#487)
- 패키지 Desktop에서 복구 비교·저장 전 변경점 보기 진입 (#655)
- 새 버전 점 표시 (#665)
- 샘플 열기·교체 (#528)

> **주요 변경**

## 작업 계획

- 범위: 현재 기능을 유지하고 Desktop package 버전을 `0.1.0-beta.2`에서 `0.0.2-beta.1`로 정정한다. 후보 검증 명령·현재 계약·색인을 맞추고, 실제 GitHub 업데이트 harness의 향후 대상을 `0.0.1-beta.4 → 0.0.2-beta.1`로 지정한다. CI local-feed fixture는 변경하지 않는다.
- 제외: 기능·Core 의미·updater/installer 동작 변경, 다운그레이드 허용, migration, 기존 tag/파일 덮어쓰기, 로컬 패키징·설치·실제 GitHub 업데이트, 병합·태그·게시·삭제. README 공개 링크와 과거 릴리스의 버전·검증 근거를 유지한다.
- 완료: 버전·문서가 일치하고 대상 로컬 검사와 준비 PR의 필수 CI가 통과한다. PR은 `Refs #632`로 연결하고 오케스트레이터의 diff 확인을 받는다. 소유자 지시로 독립 리뷰어를 생략한다. 이슈는 전체 배포·철회 완료 전 닫지 않는다.
- 검증: frozen install, Desktop 단위 테스트, workspace typecheck, docs checker, `verify-release.ts --tag v0.0.2-beta.1 --identity-only`, diff whitespace. UI 변경이 없어 로컬 브라우저·캡처는 불필요하다. Windows clean package·자산 검증·packaged·설치/업데이트·제거 검사는 필수 CI에 맡긴다.

## 후보와 후속 작업 경계

소유자는 기존 사용자가 없다고 확인하고 버전 정정을 승인했다. 이 후보는 현재 master의 기능을 유지한다. 기존 기능과 제한의 배경은 [0.1.0-beta.2 당시 기록](v0.1.0-beta.2.md)을 참고하되, 그 기록의 CI·공개 자산·호환성 사례는 이 후보를 검증한 근거가 아니다. 이 후보도 unsigned이며 Stable은 미공개다. 하위 호환성 보장이나 자동 migration을 추가하지 않는다.

오케스트레이터가 준비 PR 병합 후 검증된 master에 새 `v0.0.2-beta.1` tag를 만들고 `unsigned-beta` workflow를 실행한다. 새 공개 자산과 메타데이터 확인 후에만 기존 `v0.1.0-beta.1`·`v0.1.0-beta.2` Release·첨부 자산·원격 tag를 삭제한다. 준비 작업에서는 이 원격 작업을 실행하지 않는다. 실제 GitHub `0.0.1-beta.4 → 0.0.2-beta.1` 업데이트는 향후 실행 가능한 대상으로 지정했을 뿐 **미검증**이다.

현재 README의 `v0.1.0-beta.2` 공개 안내는 새 후보가 공개되기 전의 사실을 유지한다. 공개·철회 후 후속 문서 PR에서 README와 현행 계약을 갱신하고 과거 기록에 철회 사실을 덧붙인다. 과거 버전·해시·검증 결과를 새 버전의 결과로 바꾸지 않는다.

## 검증 상태

| 검사 | 결과 |
| --- | --- |
| 변경 전 재현 | 새 tag의 `--identity-only` 검사가 기존 app version `0.1.0-beta.2`와 불일치하여 거부됨 |
| Frozen install | `pnpm install --frozen-lockfile` 통과; lockfile 변경 없음 |
| Desktop 단위 테스트 | `pnpm --filter @ieumdoc/desktop test` 58/58 통과 |
| Typecheck | `pnpm typecheck` 통과 |
| 문서·공백 | `pnpm docs:check`, `git diff --check` 통과 |
| 후보 identity | `pnpm --filter @ieumdoc/desktop exec tsx scripts/verify-release.ts --tag v0.0.2-beta.1 --identity-only` 통과: tag/version/channel 일치. 패키지 자산 검증은 아님 |
| 준비 PR CI | PR 생성 후 확인 예정. Windows clean package·자산·packaged·Stable/Beta local-feed 설치/업데이트·제거 검사 필요 |
| 로컬 packaged·install/update·브라우저·Edge·새 profile probe | 미실행. Windows 검증은 CI에 위임하고 UI 변경이 없어 로컬 브라우저 불필요 |

새 tag·Release·자산 공개, 실제 GitHub 업데이트, 기존 Release·자산·tag 철회는 모두 미실행이다. 과거 공개 자산 검증을 이 후보의 결과로 전용하지 않는다.
